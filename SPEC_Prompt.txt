-------------------------------------------------------------
AI와 명세 작성 협업을 시작할 최초 프롬프트
-------------------------------------------------------------
나는 코덱스를 이용해서 강의와 실습에 사용할 간단한 Memo Taking 웹 앱을 만들려고 해.

대략적인 아이디어는 다음과 같아.

* 사용자가 회원가입하고 로그인할 수 있다.
* 로그인한 사용자는 제목과 본문이 있는 메모를 작성할 수 있다.
* 메모를 수정하거나 삭제할 수 있다.
* 원하는 메모는 URL로 공유할 수 있고, 공유된 메모는 로그인하지 않아도 볼 수 있다.
* localhost에서 실행하는 강의용 프로젝트다.

아직 기술 스택이나 세부 구현 방식은 확정하지 않았다. 지금 코드를 작성하지 말고, 구현에 필요한 요구사항과 설계 항목을 나와 대화하면서 하나씩 정리해 줘. 필수 기능 수준으로 단순하게 설계하고 싶다.

-------------------------------------------------------------
memo-taking-codex/AGENTS.md에 추가할 구현 규칙 프롬프트
-------------------------------------------------------------
다음 프로젝트 규칙을 AGENTS.md에 정리해 줘. 기존 규칙이 있으면 중복 없이 통합해 줘.

- 개발 서버는 uvicorn으로 실행한다.
- Python 패키지 설치는 pip 또는 uv를 사용한다.
- 상세 사양은 SPEC.md를 참조한다.
- 답변은 짧고 간결하게 작성한다.
- 불필요하게 긴 코드 예시와 장황한 설명은 피한다.

-------------------------------------------------------------
memo-taking-codex/AGENTS.md에 추가할 테스트 계획 프롬프트
-------------------------------------------------------------
계획에는 반드시 "테스트 계획" 섹션을 포함해 줘.
- pytest 파일 경로와 테스트 함수명
- 정상·경계값·실패 사례별 입력과 기대 응답(status code, body)
- 통과 판정 명령어

구현을 요청받으면 계획한 테스트를 작성하고 실행해 줘. 실패하면 원인을 수정한 뒤 재실행하고, 실제 실행 결과를 보고해 줘.

-------------------------------------------------------------
계획 모드에서 보낼 프롬프트
-------------------------------------------------------------
이 프로젝트의 핵심 페이지 경로를 설계해 줘. 인증과 실제 페이지 내용은 아직 구현하지 말고, 각 페이지에 임시 텍스트만 표시하는 단계의 계획을 세워 줘. 테스트 계획도 포함해 줘.

-------------------------------------------------------------
memo-taking-codex/AGENTS.md에 추가할 Git 규칙 프롬프트
-------------------------------------------------------------
- 새 작업은 main에서 분기한다. 브랜치 접두사는 codex/를 사용한다.
- 커밋 메시지는 Conventional Commits 형식을 사용한다.
- main에 직접 push하지 않고 PR로 변경을 검토한다.
- 커밋 전 pytest와 ruff check .를 실행한다. 도구가 아직 설치되지 않았다면 설치 여부와 실행 가능성을 먼저 확인한다.
