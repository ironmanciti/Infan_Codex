# 이슈 기술 명세 작성

1. 이슈 번호와 저장소를 확인합니다. `gh issue view <번호> --json title,body,labels,comments,state,milestone`로 이슈를 읽되, GitHub 연결이 없으면 사용자에게 이슈 본문을 요청합니다.
2. 이슈의 재현 조건과 기대 동작을 추출하고, `rg`로 관련 라우터·서비스·템플릿을 찾아 실제 코드와 대조합니다. 근본 원인은 코드 근거가 있을 때만 확정합니다.
3. 요청이 분석만인지 명세 파일 작성인지 확인합니다. 분석만 요청한 경우 파일을 만들지 않습니다.
4. 명세 파일이 필요한 경우 `specs/issue-<번호>-spec.md`에 이슈 개요, 재현·근본 원인, 최소 수정안, 변경 파일, 검증 방법, 완료 조건을 작성합니다.
5. 실행한 검증과 제안한 검증을 구분해 보고합니다. 이슈 내용이 불명확하면 가정을 표시합니다.

이 실습의 의도된 결함은 사용자가 수정을 요청하기 전까지 고치지 않습니다.
